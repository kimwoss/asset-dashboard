# 대시보드 배포 전 점검

`docs/index.html`은 3,900줄짜리 단일 파일이라 눈으로는 회귀를 못 잡는다.
아래를 **순서대로** 돌리고, 하나라도 걸리면 고친 뒤 다시 처음부터 돈다.

## 1. 자동 검사

```bash
python .claude/skills/dashboard-ship/check.py
```

통과 기준은 스크립트가 출력한다. `FAIL`이 하나라도 있으면 배포하지 않는다.

## 2. 사람이 봐야 하는 것 (스크립트로 못 잡는다)

렌더러를 고쳤다면 **켜짐/꺼짐 양쪽 상태를 실제로 렌더해 본다.**
`preview_start`로 로컬 서버를 띄우고, 실제 데이터 모양의 객체를 넣어 렌더 함수를
직접 호출한다. 잠금 화면 뒤라서 비밀번호가 필요해 보여도 **입력하지 않는다** —
렌더 함수는 전역이라 그냥 부르면 된다.

```js
renderOfficetel({ ...실제 payload 모양..., items: [...] }, 순자산);
document.getElementById("tab-officetel").style.display = "";
```

확인할 것:
- 데이터가 **없을 때** 화면이 깨지지 않는가 (빈 배열·null·빈 문자열)
- 새 열을 더했다면 `colspan`을 같이 늘렸는가
- 모바일(375px)에서 가로 스크롤이 생기지 않는가
- 다크/라이트 양쪽에서 새 색이 보이는가

## 3. 배포

로컬 서버를 끄고, `.claude/launch.json`을 만들었다면 지운다.
커밋 메시지는 **무엇을 왜 고쳤는지**를 쓴다. 겪은 함정이 있으면 본문에 남긴다 —
그게 다음 사람(대개 미래의 나)을 구한다.

새 함정을 겪었다면 `PLAYBOOK.md` §5에 한 줄 추가한다. 이건 선택이 아니다.
